The architecture constraint

Two halves. Neither can do the whole job.

Figma runs every plugin as two sealed-off programs: an engine that can read your file and a panel that can show you results. Neither can do the other’s job — so the design had to be split the same way.

The only thing that crosses

One message, sent once the analysis is done.

The engine does all the reading and scoring, then hands over a short summary of what it found. The panel turns that summary into the screens you see. Your actual design never travels.

A single typed contract — ANALYSIS_COMPLETE — is the whole interface between the two contexts. Messages are structured-cloned, so the UI can never hold a live node reference.

// shape illustrative
{
  type: "ANALYSIS_COMPLETE",
  score: 72,  // grade C
  pillars: { tokens, components, naming },
  issues: [ …ranked by severity ]
}

Findings only. No layers, no images, no file.

Why that shaped the design

Private by construction

The data stays with the engine; only the findings cross, and nothing goes online.

Two systems, one contract

Engine and interface are built and tested independently against one message.

Measurement stays pure

The engine has no screen to manage — it only measures, so the same file gives the same score.
