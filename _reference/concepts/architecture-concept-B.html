Concept B · Sequence · “Swim lanes”
The architecture constraint

The part that reads your file can’t draw. The part that draws can’t read.

Figma runs every plugin as two separate programs. Follow one analysis from click to score — your file only ever lives with the engine, and a single message is all that crosses back.

You

The designer, inside Figma.

The panel

UI iframe · React

Can draw anything. Can’t see your file.

The engine

Plugin sandbox · code.ts

Reads every layer. No screen, no internet.

  1. 01You

    You press Run analysis in the plugin panel.

  2. 02Panel → Engine

    The panel can’t read the file, so it asks the engine to.

    postMessage · run request
  3. 03Engine

    Walks every frame, instance and token in the file.

    figma.* scene API — traversal
  4. 04Engine

    Checks the four pillars and computes the drift score. Same file, same score.

    deterministic scoring, no network
  5. 05Engine → Panel

    Sends back the findings — never the file itself.

    ANALYSIS_COMPLETE
  6. 06Panel → You

    Draws the score, the pillars and each issue, screen by screen.

    React renders from the message alone
All 6 steps shown
Why that shaped the design

Because the two sides can only talk in messages, the engine and the interface became independent systems with one contract. Your design data never crosses into the panel, network access is switched off in the plugin manifest, and the engine — with no screen to manage — only measures. That’s what keeps the score private and repeatable.
